## 1. 技术规范（Technical Standards）

### 1.1 代码风格规范 → **PEP 8 + Ruff 自动化**

- **PEP 8** 是 Python 官方风格指南，核心目标是**提升可读性**（[PEP 8 原文](https://peps.python.org/pep-0008/)）。
- 工具化落地用 **Ruff**：它同时是 linter 和 formatter，是当前事实标准（[Ruff 配置文档](https://docs.astral.sh/ruff/configuration/)）。
- **关键结论（对本题的影响）**：
  - Ruff 配置可写在 `pyproject.toml` 的 `[tool.ruff]` 段，**配置随项目走**，比散落的 `.flake8` / `setup.cfg` 更现代。
  - 默认 `line-length = 88`、`indent-width = 4`、`quote-style = "double"`，与 Black 对齐 → 本工程**直接采用默认值**，不自定义，减少争议。
  - **`target-version` 可由 `pyproject.toml` 的 `requires-python` 自动推断**（文档明确说明）。因此本题只需写 `requires-python = ">=3.10"`，Ruff 会自动按 py310 检查语法，**避免 AI 生成 3.12+ 专属语法导致 3.10 不可运行**——这是本项目采纳的一条实际规范。
  - Ruff 会**自动跳过** gitignore 中的文件；且 Ruff **不合并**多份配置，只取"最近"的一份 → 不要在子目录再放 `ruff.toml`。

> **采纳决策**：`pyproject.toml` 单点配置 + `ruff check` 作为 AC-09 的客观门槛。

### 1.2 项目布局规范 → **src layout**

来源：[PyPA 官方讨论 src layout vs flat layout](https://packaging.python.org/en/latest/discussions/src-layout-vs-flat-layout/)

官方给出的三条理由：

1. **防止误用开发中的副本**：Python 解释器会把当前工作目录放在 import path 首位；若包名与已安装包同名，会优先加载当前目录版本，导致打包配置的隐性错误。src layout 把可导入代码放进 `src/`，**从结构上消除这个隐患**。
2. **强制 editable 安装只能导入"该被导入的文件"**：flat layout 会把 `README.md`、`setup.py`、`noxfile.py` 也放到 import path 上，造成"editable 能跑、正式安装跑不了"的诡异 bug。
3. **要求项目被安装后才能运行**（代价：多一步 `pip install -e .`）。

官方还给出 src layout 下**从源码直接运行 CLI** 的官方 workaround：`__main__.py` 里把包目录前插到 `sys.path`。

> **对本题的取舍（人工决策）**：
> 考核要求"**一键运行**"，而 src layout 的官方代价正是"必须先安装"。60 分钟限时场景下要求评审者先 `pip install -e .` 是**体验风险**。
> **结论**：采用 **src layout + 官方 workaround**（在 `__main__.py` 做 `sys.path` 前插），既保留 src layout 的工程规范性，又满足"`python -m excel_report` 一键运行、无需安装"。这是本次调研中**最有价值的规范适配**——把官方规范与考题约束做了显式调和，而非照搬。

### 1.3 数据清洗规范（pandas）

| 规范 | 官方依据 | 本项目应用 |
|---|---|---|
| 读入后**先做类型转换**再判断缺失 | `pd.to_numeric(errors="coerce")` 把无法解析的值变成 `NaN`（[pandas IO 指南](https://pandas.pydata.org/docs/user_guide/io.html)） | 数量/单价先 `to_numeric`，再判缺失 |
| 日期用 `pd.to_datetime(errors="coerce")` 得到 `NaT` | `errors='coerce'` 会把问题元素替换为 `NaT`/`NaN`（[pandas basics](https://pandas.pydata.org/docs/user_guide/basics.html)） | 日期列统一转 datetime，非法值→`NaT`→按缺失剔除 |
| 数值列优先用**可空整型 `Int64`** 而非 `int64` | `to_numeric` 支持 nullable dtype 与 `downcast`（[to_numeric 文档](https://pandas.pydata.org/docs/reference/api/pandas.to_numeric.html)） | 数量列用 `Int64`，避免 `NaN` 被强转导致精度/类型塌陷 |
| 缺失值判定要覆盖**空白字符串** | pandas 的 `isna()` **不认为 `"   "` 是缺失** | **本项目额外补 `astype(str).str.strip() == ""` 判定**（这是官方文档没覆盖、必须自己补的一课 → 对应用例 TC-11） |
| 去重语义 | `drop_duplicates(subset=...)` | 严格按考题"全字段去重"→ 不传 `subset` |

**⚠️ 调研发现的坑（写进风险清单）**：pandas 的 `dropna()` 只识别 `NaN`/`None`，**不识别空字符串与全空格字符串**。如果直接 `dropna()` 了事，`"   "` 这类脏数据会穿透清洗，导致报表里出现空销售员分组。这就是 TC-11 存在的理由。

### 1.4 多表写出规范

官方 `to_excel` 文档示范的标准写法（[pandas to_excel](https://pandas.pydata.org/docs/reference/api/pandas.DataFrame.to_excel.html)）：

```python
with pd.ExcelWriter("output.xlsx") as writer:
    df1.to_excel(writer, sheet_name="Sheet_name_1")
    df2.to_excel(writer, sheet_name="Sheet_name_2")
```

**关键约束**：
- 用 `with` 上下文管理器，保证 `writer.close()` 一定被调用，否则文件损坏/为空。
- `sheet_name` ≤ **31 字符**，否则 Excel 打开报错。
- 需要"追加到已存在文件"时才用 `mode="a"`（且需 `if_sheet_exists` 参数配合）→ **本题不用**，因为 C-07 要求覆盖。

### 1.5 单元格样式规范（openpyxl）

由于 `pandas.to_excel` 只写数据不写样式，需要拿到 `writer.book` / `writer.sheets` 用 openpyxl 二次加工。调研到的可用 API 与结论：

| 需求 | API | 依据 |
|---|---|---|
| 表头加粗/填色 | `openpyxl.styles.Font` / `PatternFill` | [openpyxl 样式示例](https://github.com/fcakyon/claude-codex-settings/blob/main/plugins/openai-office-skills/skills/spreadsheet/references/examples/openpyxl/styling_spreadsheet.py) |
| 列宽自适应 | `worksheet.column_dimensions[letter].width` | [GeeksforGeeks: 调整行列](https://www.geeksforgeeks.org/python/python-adjusting-rows-and-columns-of-an-excel-file-using-openpyxl-module/) |
| 冻结首行 | `ws.freeze_panes = "A2"` | [StackOverflow: freeze first column](https://stackoverflow.com/questions/73631662/how-to-freeze-first-column-using-openpyxl) |
| 数字格式 | `cell.number_format = '#,##0.00'` | openpyxl 标准 API |
| 自动筛选 | `ws.auto_filter.ref` | openpyxl 标准 API |

**中文列宽陷阱**：`len(str)` 计算列宽时，一个汉字占 **2 个字符宽度**，直接按字符数设宽度会导致中文列显示不全。必须按"东亚字符算 2"计算显示宽度。这是调研 + 实践才能发现的细节（对应用例：打开 report.xlsx 列宽检查）。

### 1.6 异常处理与退出码规范

来源：[Python 项目工程化开发指南·风格规范](https://pyloong.github.io/pythonic-project-guidelines/standard/style_rules/)、[PEP 8](https://peps.python.org/pep-0008/)

- **不要吞掉捕获到的异常**；捕获后必须记录（logging）或转译后重新抛出。
- 库代码**抛异常**，命令行入口**转译为退出码 + 中文提示**——库与 CLI 关注点分离（本项目 D-06 决策的依据）。
- 退出码约定（本题自定义）：`0` 成功 / `2` 文件不存在 / `3` 无数据 / `4` 缺列 / `5` 非 Excel / `6` 路径冲突 / `1` 未预期异常兜底。

### 3.1 从模范项目归纳出的**本项目架构结论**

综合 #2 / #3 / #6，本项目采用**三层分离 + 薄 CLI**：

```
excel_report/
├── errors.py      # 领域异常（库层对外契约）
├── loader.py      # 读取 + 列名校验（只读，绝不写入）
├── cleaning.py    # 清洗（纯函数，返回 明细 + 剔除统计）
├── aggregate.py   # 统计（纯函数，无 IO）
├── report.py      # 写出 xlsx + 样式（唯一写文件的地方）
├── cli.py         # 参数解析 + 打印摘要 + 异常→退出码
└── __main__.py    # python -m excel_report 入口（含 src layout workaround）
```

**理由**：
- 纯函数（cleaning/aggregate）**没有 IO**，pytest 可以直接构造 DataFrame 断言，不需要造 Excel 文件 → 测试快且稳定（对应用例 TC-23 可以直接测除零）。
- 只有 `loader.py` 读文件、只有 `report.py` 写文件 → **R-01（误改原文件）的审查面从"整个脚本"缩小到两个文件**，且 loader 里没有任何写 API。
- `cli.py` 独立 → 退出码映射集中一处，容易审查。

## 4. 调研对需求/用例的**反向修正**（重要）

调研不只是"查资料"，它**改写了需求**。以下三条是调研后对 `01-需求澄清清单` / `02-报表用例` 的补充：

| 来源 | 发现 | 对需求的修正 |
|---|---|---|
| pandas `dropna` 文档 | `dropna` **不识别空字符串/空白串** | 新增 **TC-11**（`"   "` 视为缺失），并在需求 §2.1 明确"空串视为缺失" |
| openpyxl 列宽实践 | 中文按字符数算宽度会**截断显示** | 需求 §6 明确"列宽自适应"要按**东亚字符宽度 ×2** 计算 |

| `to_numeric` 文档 | 数值列含 `NaN` 时 `int64` 会塌陷为 `float64`，`1.0` 显示不美观/精度隐患 | 需求 §2.1 数量列采用可空 `Int64`；用例 TC-16 覆盖 Excel 序列日期 |
