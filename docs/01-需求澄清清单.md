# 考题一 · 需求澄清清单（交给 AI 之前先书面写清）

> 依据 `Python_Vibe_Coding-lab1.docx`「交付物清单 1」与「三、过程记录与 AI 协作要求」：**先澄清需求，再交给 AI**。
> 本文档是开发前的**唯一事实来源（Single Source of Truth）**，后续代码、测试、验收均以此为准。
> 需求负责人：被考核者（人工拍板）｜文档版本：v1.0

---

## 1. 目标（Why）

把团队每月一份**脏数据** `sales_raw.xlsx`，通过一个**可一键运行**的 Python 脚本，转换为一份**统计口径明确、人工可核对、异常可读**的 `report.xlsx`。

核心诉求不是"能跑通"，而是：

| 维度 | 要求 |
|---|---|
| 结果 | 四个工作表齐全，数值与人工核对一致 |
| 过程 | 清洗规则可追溯（每条规则剔除多少行必须留痕） |
| 验证 | 有测试用例，含正常 + ≥2 个边界/异常用例 |
| 风险 | 不修改原始文件；异常输入不崩溃且有可读提示 |

---

## 2. 输入（Input）

### 2.1 原始文件

- 文件名：`sales_raw.xlsx`（路径由命令行参数指定，默认 `data/raw/sales_raw.xlsx`）
- 格式：Excel 工作簿，取**第一个工作表**；若第一个工作表为空则回退到第一个非空工作表（并告警）
- 列（字段）与期望类型：

| 列名 | 业务含义 | 期望类型 | 是否关键字段 | 说明 |
|---|---|---|---|---|
| 日期 | 销售发生日期 | datetime | ✅ **关键** | 可被 `pandas.to_datetime` 解析；支持 `2024-01-05`、`2024/1/5`、Excel 序列日期 |
| 销售员 | 销售负责人 | string | ✅ **关键** | 去除首尾空白；空串视为缺失 |
| 产品 | 产品名称 | string | ❌ 非关键 | 允许缺失，缺失记为 `未填写`，仍参与汇总（避免销售额凭空消失） |
| 数量 | 销售数量 | int | ✅ **关键** | 必须 > 0；非数字→按缺失处理 |
| 单价 | 单位价格 | float | ✅ **关键** | 必须 > 0；非数字→按缺失处理 |
| 地区 | 销售区域 | string | ✅ **关键** | 去除首尾空白；空串视为缺失 |

> **关键字段定义**：`日期、销售员、数量、单价、地区` 共 5 列。关键字段任一缺失 → 该行删除。
> 这与考核原文"删除关键字段缺失的行"一致；`产品` 不列为关键字段，属于**需求澄清时明确的边界决策**（见 §7 决策记录 D-02）。

### 2.2 脏数据清单（考题原文给定）

1. **空值**：关键字段有空单元格
2. **重复行**：全字段完全相同的行
3. **负数量 / 零数量**：`数量 <= 0` 的异常行
4. （脚本需额外防御）**非法数值**：数量/单价写成文字（如 `"待定"`）、**非法日期**（如 `"2024-13-45"`）

## 3. 输出（Output）

### 3.1 报表文件

- 文件名：`report.xlsx`（路径由 `--output` 指定，默认 `output/report.xlsx`）
- **必须包含且恰好包含以下 4 个工作表**，顺序固定：

| # | 工作表名 | 内容 | 关键列 |
|---|---|---|---|
| 1 | `明细清洗后` | 清洗后的逐行明细 | 日期、销售员、产品、数量、单价、地区、销售额 |
| 2 | `按销售员` | 销售人员维度汇总 | 销售员、订单行数、总数量、销售额、销售额占比 |
| 3 | `按地区` | 地区维度汇总 | 地区、订单行数、总数量、销售额、销售额占比 |
| 4 | `总览` | 全局 KPI 与数据质量报告 | 指标、数值（含月度总额、清洗剔除统计） |

### 3.2 统计口径（**必须无歧义**）

- **销售额 = 数量 × 单价**，逐行计算后再汇总（不是"汇总数量 × 汇总单价"）
- **金额精度**：中间计算不做四舍五入，**输出时保留 2 位小数**（`round(2)`，Excel 单元格内为数值型，方便二次计算）
- **销售额占比** = 该组销售额 ÷ 清洗后总销售额 × 100%，保留 2 位小数，单位 `%`；总销售额为 0 时占比记 `0.00`（**不得除零崩溃**）
- **月度总额**：按 `日期` 的年-月分组求和销售额，写入 `总览` 表；同时给出跨全期的**总额**
- **排序**：`按销售员`/`按地区` 一律按 **销售额降序**；并列时按名称升序（保证结果**确定性**，便于人工核对与测试断言）
- **订单行数**：清洗后明细中该组的**行数**（1 行 = 1 笔销售记录）

### 3.3 控制台输出（人可读）

运行结束打印一段摘要，必须包含：

```
[OK] 读取: data/raw/sales_raw.xlsx  (原始 120 行)
[OK] 清洗后: 98 行  (剔除 22 行)
      - 关键字段缺失 : 8 行
      - 数量<=0      : 6 行
      - 全字段重复   : 7 行
      - 非法数值/日期: 1 行
[OK] 总销售额: 123456.78
[OK] 报表已生成: output/report.xlsx (4 个工作表)
```

## 4. 边界与约束（Constraints）

| 编号 | 约束 | 实现要求 |
|---|---|---|
| C-01 | **不得修改原始文件** | 只读打开；全程不调用任何写入原始路径的 API；异常退出也不得留下半成品覆盖原文件 |
| C-02 | 原始文件不存在 | 抛出可读错误 + 非零退出码（2），提示实际查找路径 |
| C-03 | **空文件 / 空表 / 无有效数据** | 不崩溃，打印可读提示，非零退出码（3），且**不生成** report.xlsx（避免产出误导性空报表） |
| C-04 | 缺少必需列 | 报错并**列出缺失列名**与**实际表头**，非零退出码（4） |
| C-05 | 列名含首尾空白 | 自动 `strip()` 归一化后匹配（容忍 `" 数量 "`） |
| C-06 | 输出目录不存在 | 自动创建（`parents=True`） |
| C-07 | 输出文件已存在 | 直接覆盖（幂等：同样输入 → 同样输出） |
| C-08 | 幂等性 | 同一输入多次运行，输出**逐字节可复现**（不含时间戳/随机数） |
| C-09 | 依赖范围 | 仅允许 `pandas`、`openpyxl`（考核允许清单内）；不引入网络、数据库 |
| C-10 | Python 版本 | ≥ 3.10（考核要求），代码使用 3.10+ 类型注解语法 |
| C-11 | 一键运行 | `python -m excel_report --input ... --output ...`；另提供 `scripts/run_demo.py` 演示脚本 |
| C-12 | 单表行数上限 | 工作表名 ≤ 31 字符；明细表超过 Excel 上限（1,048,576 行）时报错提示而非静默截断 |

## 5. 验收标准（Acceptance Criteria，可测试）

| 编号 | 验收项 | 验证方式 | 通过条件 |
|---|---|---|---|
| AC-01 | 一键运行 | `python -m excel_report`（样例数据） | 退出码 0，生成 `report.xlsx` |
| AC-02 | 四表齐全 | 打开 report.xlsx | 表名与顺序 = `明细清洗后, 按销售员, 按地区, 总览` |
| AC-03 | 清洗正确 | 用已知脏数据小样例断言 | 关键字段缺失行删除；`数量<=0` 行删除；全字段重复行仅留 1 行 |
| AC-04 | 统计正确 | 手工计算对照 | 销售额 = 数量×单价；按销售员/地区汇总值与手算**完全一致**；月度总额一致 |
| AC-05 | 异常输入不崩溃 | 5 类异常输入逐个跑 | 每种都给出**中文可读提示** + 相应非零退出码，无 traceback 裸奔 |
| AC-06 | 原始文件未被修改 | 运行前后比对源文件 SHA256 | 哈希不变 |
| AC-07 | 幂等/确定性 | 连续运行 2 次，比对输出 SHA256 | 哈希一致 |
| AC-08 | 测试覆盖 | `pytest -q` | 正常用例 + **≥2 个**边界/异常用例全部通过 |
| AC-09 | 代码规范 | `ruff check` | 0 error |

## 6. 明确不做（Out of Scope）

- ❌ 不做可视化图表 / HTML 报告（本题只要 xlsx 四表）
- ❌ 不做多文件批量合并、不做数据库/接口（那是考题二）
- ❌ 不做 Excel 公式（输出为**静态值**，便于核对；公式会让"数值一致"验收变复杂）
- ❌ 不做自动列名模糊匹配/智能识别（`wind5516/sales-report` 那种"自动识别列"对本题是**过度设计**，会增加不确定性）
- ❌ 不做单元格式样美化到"像素级"（仅做表头加粗、列宽自适应、冻结首行、数字格式）

## 7. 决策记录（Decision Log）— 需求澄清阶段人工拍板

| ID | 决策点 | 结论 | 理由 |
|---|---|---|---|
| D-01 | "关键字段"到底哪几列？ | 日期/销售员/数量/单价/地区 5 列；**产品不算关键** | 产品缺失不应导致整笔销售额丢失；答案需写明取舍并让 AI 遵守 |
| D-02 | 产品缺失怎么处理？ | 填 `未填写` 并保留该行 | 保证"销售额守恒"：清洗前后剔除原因可完全对账 |
| D-03 | 先剔负数量还是先去重？ | **顺序固定**：① 列名归一化 → ② 类型转换 → ③ 关键字段缺失 → ④ 数量≤0 → ⑤ 全字段去重 | 顺序不同结果不同；写死顺序才能让"剔除行数"可复现、可测试 |
| D-04 | 去重用"全字段"还是关键字段？ | **全字段**（含销售额派生列之前的原始 6 列） | 严格遵守考题原文"按全字段去重"；避免把不同日期的同额订单误删 |
| D-05 | 异常时是否生成部分报表？ | **不生成**，只报错 | 部分报表会被误当作有效交付物，风险高于便利 |
| D-06 | 异常用异常类还是返回码？ | 自定义异常体系 + 在 `__main__` 统一映射为退出码 | 便于 pytest 直接 `pytest.raises`，同时满足命令行可读提示 |
| D-07 | 是否用 AI 一次生成整个脚本？ | **不**。按"数据读取→清洗→统计→写出→CLI→测试"6 小步，每步让 AI 只做一块并立即运行验证 | 符合考核"将大需求拆为可验证的小步；每步只让 AI 完成一小块并及时运行验证" |

## 8. 风险清单与人工审查点（Risk Register）

| 风险 | 影响 | 缓解措施 | 审查方式 |
|---|---|---|---|
| R-01 AI 误用 `inplace=True` 或直接覆写原文件 | **高风险**：原始数据被破坏 | 只读加载；输出路径与输入路径做**同一路径断言**，相同则拒绝执行 | 人工 Code Review + AC-06 哈希比对 |
| R-02 金额浮点误差累加 | 统计值与人工核对不一致 | 输出统一 `round(2)`；测试用整数/两位小数构造用例断言精确相等 | 人工手算对照（AC-04） |
| R-03 除零（总销售额为 0 时算占比） | 崩溃 | 显式判零分支 | 边界用例覆盖 |
| R-04 去重把不应合并的行删掉 | 数据丢失 | 明确"全字段去重"口径，写入需求文档；测试断言重复行只留 1 行 | 人工核对剔除明细 |
| R-05 AI 擅自重构/引入不必要依赖（如 xlsxwriter、polars） | 超出考题允许清单，风险不可控 | 需求文档写死依赖范围 C-09；Code Review 拒绝额外依赖 | 人工审查 `requirements.txt` 与 import |
| R-06 异常时 traceback 直接抛给用户 | 验收标准"可读提示"不达标 | 自定义异常 + 顶层统一捕获 | AC-05 |
| R-07 Excel 序列日期（如 45292）被当数字 | 日期解析错误导致月度分组错乱 | 类型转换前对数值型日期做显式分支处理 | 边界用例覆盖 |
