## 1. 架构设计

### 1.1 分层与职责

```
            ┌──────────────────────────────────────────┐
 用户输入 → │ cli.py  参数解析 / 打印摘要 / 退出码映射   │  ← 唯一处理 SystemExit 的地方
            └───────────────────┬──────────────────────┘
                                │ 调用
            ┌───────────────────▼──────────────────────┐
            │ pipeline.py  run(input, output) 编排      │  ← 纯编排，不含业务规则
            └───┬───────────┬───────────┬───────────┬──┘
                │           │           │           │
       ┌────────▼──┐  ┌─────▼─────┐  ┌──▼───────┐  ┌▼─────────┐
       │ loader.py │  │cleaning.py│  │aggregate │  │ report.py│
       │ 读取+校验 │  │  清洗      │  │  统计     │  │ 写 xlsx  │
       │  ⚠️ 只读  │  │  纯函数    │  │  纯函数   │  │ ⚠️ 唯一写 │
       └───────────┘  └───────────┘  └──────────┘  └──────────┘
                │                                      │
                └──────────┬───────────────────────────┘
                    ┌──────▼──────┐
                    │ errors.py   │ 领域异常（对外契约）
                    └─────────────┘
```

### 1.2 设计原则（每条都有对应的风险缓解）

| 原则 | 说明 | 缓解的风险 |
|---|---|---|
| **单写点** | 只有 `report.py` 调用写文件 API | R-01（误写原文件）审查面收敛 |
| **单读点** | 只有 `loader.py` 打开输入文件，且 `read_only` 语义 | R-01 |
| **纯函数核心** | `cleaning` / `aggregate` 不碰文件系统 | 测试无需造 Excel，TC-23 可直接测除零 |
| **异常即契约** | 库层抛 `ReportError` 子类，CLI 层统一映射退出码 | R-06、D-06 |
| **顺序固定** | 清洗步骤编号写死在文档与代码注释中 | D-03、AC-03 可复现 |
| **无隐式状态** | 不读环境变量、不读当前时间、不用随机数 | C-08 幂等性 |

## 2. 模块接口设计

### 2.1 `errors.py` — 领域异常

```python
class ReportError(Exception):          # 基类；带 .exit_code
    exit_code: int = 1

class InputFileNotFoundError(ReportError):   exit_code = 2   # C-02
class EmptyDataError(ReportError):           exit_code = 3   # C-03 无任何数据行
class NoValidDataError(ReportError):         exit_code = 3   # C-03 全部被剔除
class MissingColumnsError(ReportError):      exit_code = 4   # C-04
class InvalidWorkbookError(ReportError):     exit_code = 5   # C-03 非 Excel/损坏
class SamePathError(ReportError):            exit_code = 6   # R-01 防覆写
```

**设计要点**：`exit_code` 作为**类属性**而非构造参数 → 异常类自身就是"错误类型 → 退出码"的映射表，CLI 里不需要 `if isinstance(...)` 长链。

### 2.2 `loader.py`

```python
def load_raw(path: Path) -> pd.DataFrame:
    """读取原始 xlsx 的第一个非空工作表。只读，绝不写入。"""

def normalize_columns(df: pd.DataFrame) -> pd.DataFrame:
    """列名 strip 归一化（C-05）。"""
```

`load_raw` 的检查顺序（**顺序本身是规格**）：

1. `path.exists()` → 否则 `InputFileNotFoundError(实际路径)`
2. 用 `pd.ExcelFile` 打开 → `zipfile.BadZipFile` / `InvalidFileException` → `InvalidWorkbookError`
3. 选表：第一个工作表；若为空则找第一个非空表（并告警）
4. 表完全无行 → `EmptyDataError`
5. `normalize_columns`
6. 必需列校验 → `MissingColumnsError(缺失列, 实际表头)`

### 2.3 `cleaning.py`

```python
@dataclass(frozen=True)
class CleaningStats:
    raw_rows: int
    cleaned_rows: int
    dropped_missing: int
    dropped_nonpositive: int
    dropped_duplicate: int
    dropped_invalid: int
    @property
    def dropped_total(self) -> int: ...

def clean(df: pd.DataFrame) -> tuple[pd.DataFrame, CleaningStats]:
    """按固定顺序清洗。返回 (明细, 统计)。"""
```

**清洗顺序（写死，对应 D-03）**：

| 步 | 操作 | 计数归入 |
|---|---|---|
| ① | 列名归一化 | —（loader 已做） |
| ② | 类型转换：日期→datetime、数量→`Int64`、单价→float | 转换失败计数 → `dropped_invalid` |
| ③ | 关键字段缺失（NaN **或** strip 后为空串） | `dropped_missing` |
| ④ | 数量 ≤ 0 | `dropped_nonpositive` |
| ⑤ | 全字段去重（原始 6 列） | `dropped_duplicate` |
| ⑥ | 计算 `销售额 = 数量 × 单价` | — |

**为什么②要单独计数**：把"文字当数量"这种脏数据和"关键字段为空的脏数据"分开，人工核对方便（AC-03 要求"剔除原因可对账"）。

**⚠️ 关键实现细节（来自调研）**：`pandas.dropna()` 不认识 `"   "`。必须显式做
`df[col].astype("string").str.strip().eq("").fillna(True)` 的合并判定。

### 2.4 `aggregate.py`

```python
def by_salesperson(detail: pd.DataFrame) -> pd.DataFrame
def by_region(detail: pd.DataFrame) -> pd.DataFrame
def monthly_totals(detail: pd.DataFrame) -> pd.DataFrame
def overview(detail: pd.DataFrame, stats: CleaningStats) -> pd.DataFrame
def _with_share(g: pd.DataFrame) -> pd.DataFrame   # 加"销售额占比"，含除零保护
```

**排序契约（决定测试能否断言）**：`sort_values(["销售额", "组名"], ascending=[False, True])` → 销售额降序、并列按名称升序（TC-04）。

**除零保护**：
```python
total = g["销售额"].sum()
g["销售额占比"] = (g["销售额"] / total * 100).round(2) if total else 0.00
```

### 2.5 `report.py`

```python
SHEET_DETAIL   = "明细清洗后"
SHEET_BY_PERSON = "按销售员"
SHEET_BY_REGION = "按地区"
SHEET_OVERVIEW  = "总览"

def write_report(output: Path, *, detail, by_person, by_region, overview) -> None
```

- 用 `pd.ExcelWriter(output, engine="openpyxl")` 上下文管理器（调研 §1.4）
- 每个 df `to_excel(..., index=False)` —— **不写 index**，否则报表多一列无意义序号
- 写完后通过 `writer.book` / `writer.sheets` 加工样式：
  - 表头：`Font(bold=True, color="FFFFFF")` + `PatternFill("solid", fgColor="4472C4")` + 居中
  - 列宽自适应：**东亚字符宽度按 2 计**（调研 §1.5 的坑）
  - `freeze_panes = "A2"`
  - `auto_filter.ref = ws.dimensions`
  - 金额列 `number_format = "#,##0.00"`，占比列 `0.00"%"`（因为值已 ×100）
- **工作表数量断言**：写出后断言恰好 4 张，顺序正确

### 2.6 `cli.py`

```python
def build_parser() -> argparse.ArgumentParser
def main(argv: list[str] | None = None) -> int
```

参数：

| 参数 | 简写 | 默认 | 说明 |
|---|---|---|---|
| `--input` | `-i` | `data/raw/sales_raw.xlsx` | 原始表路径 |
| `--output` | `-o` | `output/report.xlsx` | 报表输出路径 |
| `--quiet` | `-q` | False | 只输出错误 |

**同一路径检查**：`input.resolve() == output.resolve()` → `SamePathError`（R-01 硬防线）。

摘要输出格式见需求 §3.3。**「不生成部分报表」**：所有可能抛异常的步骤（读/清洗/统计/路径检查）都在 `write_report` **之前**完成 → 只要开始写，就说明数据已全部就绪（D-05 的结构性实现，而不是靠 try/except 回滚）。

## 3. 版本管理规则

### 3.1 版本号语义

采用 `MAJOR.MINOR.PATCH`：

| 变化 | 版本位 | 示例 |
|---|---|---|
| 需求口径变更（改清洗规则/统计口径） | MAJOR | `1.0.0 → 2.0.0` |
| 新增工作表/新增 CLI 参数 | MINOR | `1.0.0 → 1.1.0` |
| 修 bug、样式调整 | PATCH | `1.0.0 → 1.0.1` |

**注意**：因为"需求口径"直接决定报表数值，**口径变更是 MAJOR**——这是本项目的特殊约定，写进 `CHANGELOG.md` 抬头。

### 3.2 版本三处同步

`src/excel_report/__init__.py` 的 `__version__`、`pyproject.toml` 的 `version`、`CHANGELOG.md` 最新条目，**必须一致**（由 `tests/test_version.py` 断言，防AI改漏）。

### 3.3 记录规范

- `CHANGELOG.md`：Keep a Changelog 格式，分 `Added / Changed / Fixed / Docs`
- `docs/04-AI协作过程记录.md`：每次 AI 交互记 `Prompt → AI 输出摘要 → 人工审查结论 → 采纳/拒绝理由`
- `docs/05-代码修改diff.md`：关键修改的 diff

## 4. 测试策略

| 层 | 手段 | 是否需真实 xlsx |
|---|---|---|
| 单元（cleaning/aggregate） | 直接构造 DataFrame 断言 | ❌ 不需要（快） |
| 集成（pipeline） | `tmp_path` 写临时 xlsx → 读回断言 | ✅ 需要 |
| CLI（退出码） | `subprocess` 或直接调 `main()` 捕获 `SystemExit` | 部分 |

**断言必须是"真断言"**：不只断言"没抛异常"，而要比对**具体数值**（AC-04 要求与人工核对一致）。这是 Code Review 的重点（S6 步骤的人工验证动作）。
